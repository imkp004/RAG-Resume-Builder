## IAM Compliance Auditor — Architecture and Build
**Category:** Project — Cloud Security / Automation
**Source:** Personal project — AWS IAM Compliance Auditor with AI-Assisted Remediation
**Skills:** AWS Lambda, Terraform, Python, IAM, S3, boto3

Designed and built a fully automated, serverless AWS pipeline that audits IAM roles and policies for least-privilege violations. Built a Python Lambda that discovers every IAM role in an account, inspects both attached and inline policies, and flags statements granting wildcard action and wildcard resource on an Allow effect — the highest-severity least-privilege violation. Implemented a policy-document cache to avoid redundant API calls when many roles share the same managed policy, reducing IAM API throttling risk at scale. Structured findings with stable, deterministic IDs (hashed from role, policy, and statement) so the same violation can be tracked as still-open across repeated runs. Provisioned all infrastructure — S3 storage, least-privilege IAM roles, Lambda functions — using Terraform.

## IAM Compliance Auditor — AI Integration and Full Automation
**Category:** Project — GenAI / Cloud Automation
**Source:** Personal project — AWS IAM Compliance Auditor with AI-Assisted Remediation
**Skills:** Amazon Bedrock, Claude, EventBridge, SNS, S3 Event Notifications, Prompt Engineering

Integrated Amazon Bedrock (Claude Haiku) into the pipeline to convert raw IAM findings into a structured, human-readable risk summary with specific per-finding remediation commands, rather than requiring a human to manually interpret raw JSON output. Automated the full pipeline end-to-end: an Amazon EventBridge rule triggers the audit Lambda on a schedule; writing a new report to S3 automatically triggers a summarizer Lambda via an S3 event notification, which calls Bedrock and publishes a concise alert (finding count plus a pointer to the full report) to Amazon SNS for email delivery. Deliberately designed alerts to stay short — for triage — while full remediation detail lives in S3, avoiding alert fatigue. Confirmed the entire pipeline running unattended on its real production schedule, with zero manual intervention from trigger to email delivery.

## IAM Compliance Auditor — Production Debugging and Least-Privilege Security Design
**Category:** Project — Troubleshooting / Security Engineering
**Source:** Personal project — AWS IAM Compliance Auditor with AI-Assisted Remediation
**Skills:** IAM Least-Privilege Design, AWS Debugging, Root Cause Analysis, boto3, AWS Bedrock

Deliberately scoped narrow, least-privilege IAM roles for each Lambda function rather than granting broad permissions to avoid friction, and updated each role's policy explicitly every time the corresponding Lambda's code gained a new capability. Diagnosed and resolved a series of real, non-obvious AWS production issues surfaced only once code ran under its actual restricted role rather than broader personal credentials: a missing `iam:GetRolePolicy` permission causing silent `AccessDenied` errors; Amazon Bedrock's requirement for IAM permission on both an inference profile ARN and its underlying foundation model ARN; a distinction between `s3:ListBucket` (bucket-level) and `s3:GetObject`/`s3:PutObject` (object-level) that caused S3 to return misleading generic `AccessDenied` errors; a genuine read-after-write race condition in an S3-event-triggered Lambda, resolved with a targeted retry mechanism; and a URL-encoding bug in S3 event notification payloads (a literal "+" character in a timestamp-based object key) that caused persistent `NoSuchKey` errors until decoded with `urllib.parse.unquote_plus`. In each case, diagnosed root cause by querying AWS's actual live state directly (`aws iam get-role-policy`, CloudWatch Logs) rather than assuming configuration was correct.
